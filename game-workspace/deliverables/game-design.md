# 游戏设计文档（一页版 GDD）——《节气跳跳》灰盒原型指导

- 阶段：`01-concept` ｜ 角色：designer ｜ 日期：2026-10-27 ｜ 配套决策文档：`01-concept.md`
- 用途：直接指导 `03-prototype` 灰盒实现。本文档不含实现代码；工程结构与版本选型以 `02-architecture` 为准。数值均为初值，调参不改规则。
- 工作名：《节气跳跳》（暂定，H1 可改）。

## 1. 一句话与设计支柱

按住蓄力、松手起跳，落到下一块「节气石」上：越靠中心分越高，落空即败。

支柱：① 单指即可完成一切操作；② 死亡永远是自己蓄力失误，不靠随机惩罚；③ 每次 Perfect 都有可感知的声画反馈；④ 任何界面两步内可重开一局。

## 2. 核心循环

观察台距 → 按住蓄力（角色下蹲压缩 + 蓄力音）→ 松手起跳（抛物线）→ 落点判定（Perfect：高音 + 轻振动 + 闪光；站稳：普通音；坠落：失败）→ 得分与连击 → 下一块台座由随机生成器给出 → 追求更高分与新纪录。

## 3. 状态机

| 状态 | 进入条件 | 离开事件 → 目标 |
| --- | --- | --- |
| Boot | 启动 | 资源与存档载入完成 → Home |
| Home | Boot 完成 / 从 Paused、GameOver 返回 | 点「开始」→ Playing；点音效图标 → 切换开关（停留） |
| Playing | Home 开始 / GameOver、Paused 重开 | 坠落 → GameOver；点暂停 → Paused；切后台 → Paused |
| Paused | 暂停按钮 / wx.onHide | 继续 → Playing；重开 → Playing（重置）；回首页 → Home |
| GameOver | Playing 中坠落判定成立 | 「再来一局」→ Playing（重置）；「回首页」→ Home |

- 切后台：Playing 时 `wx.onHide` 一律进入 Paused（Web 冒烟环境由适配层模拟）。
- 全局无其他状态；首局教程以 Playing 内覆盖层实现，不单独建状态。

## 4. 规则示例（数值走查）

设定：台座顶面半宽 halfW=80px（此例），Perfect 阈值 18px，安全内缩 4px。落点偏移 = 落点 X − 台面中心 X。

- 例 1：偏移 10px ≤ 18 → **Perfect**：+2 分，连击数 1，连击奖励 +min(1−1,4)=+0，本跳共 +2。
- 例 2：连击数已达 3 时再次 Perfect：+2 + min(3−1,4)=+2 → 本跳共 +4。
- 例 3：偏移 55px，18 < 55 ≤ halfW−4=76 → **站稳**：+1 分，连击清零。
- 例 4：偏移 74px，处于 halfW−20=60 与 76 之间 → 判定仍为站稳 +1，但播放「踉跄」摇晃动画与提示音（纯表现层，不影响判定）。
- 例 5：偏移 80px > 76 → **坠落** → GameOver。
- 例 6：新纪录结算：GameOver 层显示「新纪录！」高光与总分数，此即单局「胜利」体验。

## 5. 数值初值表（逻辑模块参数，全部可调）

| 参数 | 初值 | 说明 |
| --- | --- | --- |
| 蓄力时长上限 | 0.9s | 蓄满后角色持续抖动提示 |
| 跳跃距离映射 | d = 120 + 520 × clamp(t/0.9, 0, 1) px | t=按压秒数；750 设计宽下成立 |
| 跳跃表现 | 时长 0.55s、弧顶高 180px | 视觉层固定，与判定无关 |
| Perfect 阈值 | ≤18px | 判定阈值一 |
| 站稳阈值 | ≤ halfW − 4px | 判定阈值二；超出即坠落 |
| 踉跄动画区间 | halfW−20 < 偏移 ≤ halfW−4 | 仅表现 |
| 台面宽度 w | 分数 0–9：150–200；10–29：110–180；30+：90–160 px | 随机区间，随分数收紧 |
| 台间距 gap | 分数 0–9：140–260；10–29：160–340；30+：180–420 px | 随机区间，随分数拉远 |
| 首台座 | w=200，居中 | 保证第一跳必可成功 |
| 计分 | 站稳 +1；Perfect +2 + min(连击数−1, 4) | 连击从第 2 次 Perfect 起有奖励 |
| 连击里程碑 | 每 5 连击播放一次专属音效+闪光 | 无功能奖励，仅反馈 |

随机生成器使用可注入种子（StageGen），保证可测试与可复现。

## 6. 教程（仅首局）

覆盖层三步，全程可点右上「跳过」：

1. 高亮提示「按住屏幕任意处蓄力」——等待玩家首次按下后进入下一步。
2. 提示「松手起跳」——等待首次释放后进入下一步。
3. 提示「越靠近中心分越高」——首次落点结算后展示对应 Perfect/站稳反馈，教程完成。

完成或跳过即写 `tutorialDone=true`，之后不再出现；清空存档可复现教程。

## 7. 存档

- 键名：`save_v1`；内容 JSON：`{v:1, best:0, games:0, sound:true, haptics:true, tutorialDone:false}`（字段为初值示例）。
- 读取：Boot 时一次。写入时机：最高分刷新、设置变更、教程完成、GameOver（games+1）。
- 适配层接口（逻辑层仅依赖接口，不依赖 wx）：`storage.get(key) / storage.set(key, value)`；微信实现用 `wx.setStorageSync`，Web 冒烟实现用 `localStorage`。
- 坏档兜底：解析失败视为无档，用默认值重建，不崩溃。

## 8. 声音与振动

- 音效清单（短合成音，具体格式 02 阶段定）：蓄力起始、起跳、落地普通（中音）、落地 Perfect（高音）、连击里程碑、坠落、UI 点击。
- 开关：Home 与暂停面板各一处，切换即时生效并写存档；无背景音乐（首版不做）。
- 振动：Perfect 时 `wx.vibrateShort` 轻振动，受 `haptics` 开关控制；Web 环境自动跳过。

## 9. 横竖屏与安全区

- 固定竖屏，设计分辨率 750×1334，fitWidth。
- 顶部 UI 从微信胶囊下方开始：适配层用 `wx.getMenuButtonBoundingClientRect()` 计算胶囊底边，Web 冒烟用常量模拟；异形屏用安全区数据避让底部。
- 暂停按钮放左上角、与胶囊同排但不重叠。

## 10. 失败与重开

- 坠落 → 短坠落动画（≤0.6s）→ GameOver 层：本局分、最高分（新纪录高光）。
- 主按钮「再来一局」位于屏幕下 1/3 拇指区，高度 ≥88px（设计像素）；点击即重开，无确认弹窗。失败→新开一局 ≤2 次点击（实际 1 次）。

## 11. 输入细节

- 按压起点不限（屏幕任意处），多点触控只取第一指；松手即起跳，与按住时长一一对应（§5 映射）。
- 蓄力中再次点按不叠加；GameOVer/暂停面板打开时忽略场内输入。

## 14. 验收标准（可测试条目）

- AC-1：纯逻辑模块（蓄力映射、落点判定、计分连击、台座生成、存档序列化）单元测试全部通过，不依赖 Cocos 与 wx；由后续阶段 `game/scripts/verify.mjs` 承载（本阶段不创建）。
- AC-2：教程仅首局出现，清档后可复现（§6）。
- AC-3：音效/振动开关即时生效，重启后保留。
- AC-4：失败→下一局开始 ≤2 次点击。
- AC-5：Playing 切后台回前台自动暂停，继续后无跳帧误判。
- AC-6：竖屏固定；iPhone X 等机型模拟下 UI 不与胶囊重叠、不被底部安全区遮挡。
- AC-7：单局时长中位数落在 30 秒–2 分钟（试玩抽样记录）。
- AC-8：目标设备 60 FPS、低端机 ≥30 FPS；原型阶段以开发者工具帧率面板记录，真机实测留待 07 阶段。
- AC-9：首屏可交互 <3 秒（工程目标，实测记录）。
- AC-10：主包 <4 MB（灰盒阶段天然满足，正式开发复测）。

## 15. 模块边界提示（供 02-architecture 细化）

- `logic/`（纯 TypeScript，零 Cocos/wx 依赖，全部可单测）：ChargeSim（蓄力→距离）、LandingJudge（阈值判定）、ScoreService（计分/连击）、StageGen（种子化台座序列）、SaveData（序列化与校验）。
- `render/`：Cocos 场景与表现层（挤压拉伸、踉跄、Perfect 特效、动画时长）。
- `platform/`：storage、vibrate、audio、生命周期（onHide/onShow）、胶囊/安全区尺寸、广告位空接口（不实现）。
- 原则：所有 `wx` 调用只出现在 `platform/`；规则改动不改渲染，渲染改动不改逻辑。
